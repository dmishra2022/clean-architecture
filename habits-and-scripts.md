# Daily habits and conversation scripts

[← Back to index](README.md)

## Daily (45–90 min protected)

- Review **2–3 PRs** (aggregates, boundaries, tests).  
- Scan on-call / incident channel — architectural follow-ups when relevant.  
- One learning block: wiki, postmortem, or spec diff.

## Weekly

- **Office hours** (30 min, optional).  
- Update decision log (ADR links).  
- Product sync on next-quarter epics — flag spikes early.  
- Copy [personal-tracker.md](personal-tracker.md) for the week.

## Credibility killers (avoid)

- Big diagrams without migration path.  
- “Clean architecture” renames without behaviour change.  
- Blocking delivery without a phased option.  
- Technical changes that touch audit trails without compliance awareness.  
- Meetings only — **visible commits** early.

## Scripts (adapt names)

**EM (week 1):**  
“I want clarity on decision rights: which calls are mine alone, which need tribe architecture forum, and which need risk sign-off. I’ll bring a context map and risk register by day 30.”

**Compliance (week 2):**  
“What artefacts do auditors request most often, and which systems make that painful? I’ll prioritise architecture work that shortens audit evidence collection.”

**SRE (week 2):**  
“Which user journey keeps you up at night? I’d like to co-own SLO definition and one game day in the next 60 days.”

**Product (week 3):**  
“Give me three client escalations from the last quarter that engineering could have prevented with architecture investment—I’ll turn one into RFC-001.”

**Peer architect (week 4):**  
“I’ll review your next ADR if you sanity-check my context map integrations—especially screening ↔ data corpus boundaries.”
